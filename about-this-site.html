How This Site Was Built

Hand-written HTML, CSS and JavaScript, version-controlled with Git and deployed on GitHub Pages. No framework, no build step, no dependencies.

Components

Markup and stylingHTML5 and CSS, written by hand. One shared stylesheet across every page, built on CSS custom properties and CSS Grid. No preprocessor and no utility framework.
InteractivityPlain JavaScript in two files, sim.js and montecarlo.js, loaded with defer. No bundler, so the browser runs the file in the repository.
Charts and figuresStatic figures generated in Python with Matplotlib and committed as PNG. Interactive charts drawn to a <canvas> in JavaScript. No charting library.
TypographySpace Grotesk and Inter, both open licence, subset and served from this domain rather than a third-party font host.
Version controlGit, with the full history and every script public in the repository.
Hosting and deploymentGitHub Pages, served from the main branch. Deployment is git push.
AnalyticsGoatCounter. Cookieless, and the only third-party request on the site.

What I built

  • A physics solver running in the browser. The lap time model was written and validated in Python. I ported the solver to JavaScript so the page re-solves the lap whenever a slider moves, and checked both implementations against the same fixed inputs so the answers agree.
  • Interactive charts from scratch. Speed traces, strategy curves and a Monte Carlo distribution, drawn to canvas and redrawn on every parameter change, including axis scaling, legends and device-pixel-ratio handling.
  • A figure pipeline shared across two languages. One palette file read by both the Python and MATLAB plotting scripts, so every figure on the site matches the page it sits in and can be regenerated from source.
  • Accessibility. Skip links, a single h1 per page and a heading order that does not skip levels, text alternatives on every image and figure, visible focus styles, and animation suppressed under prefers-reduced-motion. Nothing is encoded by colour alone.
  • Search and link previews. Per-page meta descriptions and canonical URLs, Open Graph and Twitter card tags so a shared link renders as a card, JSON-LD structured data, a sitemap, a robots file and a 404 page that routes back into the site.
  • Performance. Explicit image dimensions so nothing reflows on load, lazy loading below the fold, metadata-only video preloading, and preloaded fonts with font-display: swap.

Limitations

  • No automated tests. The JavaScript solver was checked against the Python output by hand. Nothing currently stops a future edit changing a result silently.
  • Shared markup is duplicated. The navigation and footer are copied into every page, so changing either is a multi-file edit. That is the cost of having no build step, and at this number of pages it is still the cheaper trade.
  • Dark mode only. The site does not respond to prefers-color-scheme.
  • Not tested across a browser matrix. Developed and checked in Chrome and Firefox on Windows, and on mobile Safari.

Relevant skills

  • Taking a project from nothing to deployed and publicly accessible, including hosting and the release process.
  • Reimplementing a validated numerical model in a second language and verifying the two agree.
  • Version control with Git and a deployment workflow I maintain myself.
  • Building to accessibility and performance requirements rather than treating them as polish.
